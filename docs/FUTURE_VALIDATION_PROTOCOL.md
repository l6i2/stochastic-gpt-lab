# FUTURE_VALIDATION_COHORT protocol

**Protocol status:** preregistered collection protocol; evaluation remains
sealed and unauthorized. This is a separate prospective cohort, not a repair,
relabeling, extension, or reuse of either legacy holdout.

## Frozen start rule

Start ingesting only at **2026-10-19 00:00:00 UTC**. The last signal timestamp
in the frozen legacy TRAIN membership file is **2025-08-19 08:04:59.999 UTC**.
The fixed start is strictly later than that research cutoff and later than the
last historical source block already used in this project. The collector has
no option to override the start time and performs no backfill. It rejects data
before the fixed start.

The old split manifest's FINAL_TEST boundary remains unchanged and inaccessible
to this collector. New observations are written to a new cohort directory and
are never joined to the legacy master or its splits. The collector does not
read legacy FINAL_TEST rows, the legacy Discovery Validation partition, or
their outcome files. The cohort is prospective and physically separated; it
does not convert, reuse, or unlock the historical FINAL_TEST.

## Fixed data contract

- Instrument: exact broker symbol `US30Cash`; no alias substitution.
- Timeframe: M5, UTC bar-open timestamps.
- Source: the uniquely detected, active XM MT5 terminal, connected to DEMO;
  collector uses the read-only MetaTrader 5 Python integration, with no login
  credentials supplied and no order/position functions.
- Capture: `COPY_TICKS_ALL` quotes plus M5 OHLC, tick volume, real volume, and
  spread for closed UTC calendar days. The collector waits for a two-hour
  settlement lag and partitions tick queries into one-hour UTC windows.
- Causality: only raw observations are captured. No feature, signal, target,
  label, or PnL is generated by the collector. Any later derived feature must
  be available at or before its signal/snapshot timestamp; targets must remain
  in a separate artifact and never enter the feature whitelist.
- Strategy contract for a later, separately authorized evaluator: Stochastic
  K=5, D=3, Slowing=3, zones 20/80, MAIN_K re-entry trigger, next-bar entry,
  TP=240, SL=180, time exit 100 M5 bars, virtual FOLLOW and INVERT paths. The
  collector itself does not evaluate or change this strategy.
- Safety: `LIVE_TRADING=false`; `demo_execution=false`; no trading APIs.

The MT5 Python API documents `copy_ticks_range` and `copy_rates_range` as
retrieval functions against the connected terminal, and requires UTC-aware
datetimes because terminal bar/tick times are stored in UTC. Bars returned are
limited by the history available to the terminal and its chart history limit;
therefore a collection PASS means the query completed and artifacts were
hashed, not that the broker supplied gap-free history. Coverage gaps and
provider limitations must be audited before any later evaluation.
[MQL5 `copy_ticks_range`](https://www.mql5.com/en/docs/python_metatrader5/mt5copyticksrange_py),
[MQL5 `copy_rates_range`](https://www.mql5.com/en/docs/python_metatrader5/mt5copyratesrange_py),
[MQL5 `initialize`](https://www.mql5.com/en/docs/python_metatrader5/mt5initialize_py).

## Physical isolation and sealed use

Runtime data live only at
`outputs/future_validation_cohort/cohort_20261019/`. That path is ignored by
Git and explicitly refused by TRAIN CSV and Parquet readers. TRAIN pipeline
commands that read, build, score, rank, or validate against the contaminated
legacy Discovery Validation split return `BLOCKED` before stage execution.
TRAIN remains available through its frozen TRAIN partition only.

The runtime `cohort_manifest.json` starts with `evaluation_authorized=false`
and `train_access_allowed=false`. Each UTC-day segment is immutable, records
row counts, exact interval, byte length, and SHA-256 for its raw tick and bar
files. The manifest has its own SHA-256 sidecar and a previous-manifest hash
chain. An altered manifest, mismatched segment, wrong terminal, non-DEMO
account, missing symbol, or API error stops collection fail-closed.

The cohort cannot participate in hypothesis generation, threshold selection,
ranking, or tuning. A read-only single-use evaluator is implemented at
`python/future_validation_evaluator.py`; it requires a frozen candidate and
SHA-256 sidecar, an independently audited mature/causal evaluation table, and
a matching explicit one-use authorization token. Its synthetic tests do not
open the real cohort. It verifies candidate, cohort manifest, health report,
evaluation table, evaluator, and protocol hashes, consumes authorization before
reading outcomes, and writes a hash-bound audit trail. See
[`PROSPECTIVE_EVALUATION_PROTOCOL.md`](PROSPECTIVE_EVALUATION_PROTOCOL.md) for
the frozen metrics and PASS/FAIL/INCONCLUSIVE gates. The separate maturity
thresholds remain frozen in `docs/FUTURE_VALIDATION_READINESS_RULE.md`. This
protocol does not authorize scoring or opening FINAL_TEST.

Integrity and maturity metadata are produced by
`python/future_cohort_health.py`. It reads raw ticks/bars only and calculates
signal counts, coverage, quote quality, fixed session/regime support and gaps;
it has no outcome fields or scoring path. Maturity stays false until the exact
XM server calendar is independently verified, the frozen candidate/evidence
requirements pass, and the raw cohort passes all frozen quality gates.
Feature-only drift rules are in [`DRIFT_MONITOR_PROTOCOL.md`](DRIFT_MONITOR_PROTOCOL.md).

## Data-quality acceptance before any future evaluation

Before the cohort could be considered usable, an independent audit must verify
the manifest chain, every file hash, timestamp ordering and bounds, UTC day
coverage, M5 bar continuity against market sessions, tick/bid/ask validity,
source identity, duplicate-boundary behavior, and any missing intervals. It
must also reproduce the event and causal feature producer on synthetic fixtures
and confirm the whitelist/target separation. Collection alone is not a
validation result and cannot promote a rule or model.
