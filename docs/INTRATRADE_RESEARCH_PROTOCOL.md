# Intra-trade research protocol (round 2)

## Status and data gate

This protocol is defined before any intra-trade validation. The currently frozen master event dataset contains one record per Stochastic signal, causal features at signal time, and terminal FOLLOW/INVERT outcome summaries. It does **not** contain the intervening M5 bars or quotes, per-bar unrealized PnL, or time-indexed feature states. Therefore it cannot support valid snapshots at +1, +2, +3, +5, +10, +15, +20, +30, or +50 bars. No synthetic snapshots are created from terminal MFE/MAE or exit fields.

To unlock snapshot construction, a new, separately versioned source must provide, for every signal and both virtual directions, the actual post-entry quote/bar path through closure. Required provenance includes `signal_id`, path timestamp, bid/ask or the exact price series used by the tester, M5 OHLC/tick volume, the tester's virtual position state, and causal stochastic/HA/profile inputs. The source must be generated by an instrumented research run using the unchanged strategy, real-tick model, and `LIVE_TRADING=false`. Exact tester event ordering and spread handling must be preserved. A bar-only approximation is a distinct dataset and cannot be mixed with tick-quote outcomes.

## Snapshot contract

One row per `(signal_id, trade_direction, snapshot_bar)` only when the virtual position is still open at that completed bar. `snapshot_time` and `feature_max_time` must not exceed the snapshot bar close. Split membership is inherited from the original `signal_id`; no signal can cross splits. Features are computed as-of snapshot only. Future labels are stored separately and never enter the feature whitelist. FINAL_TEST snapshots are neither created nor inspected during discovery.

Future labels may include TP-before-SL, SL-before-TP, future directional advantage, favorable/adverse excursion after snapshot, fixed-rule reversal event, profit erosion, and recovery after drawdown. Every threshold and event definition must be hashed before validation. All labels must respect actual trade closure and censored end-of-data status.

## Operational guard

This is research-only. No dynamic exit, position reversal, skip, or trade execution policy may be deployed from these analyses. Baseline remains the existing fixed TP 240, SL 180, TIME_EXIT 100 behavior. `LIVE_TRADING=false`; no demo execution is authorized by this protocol.
